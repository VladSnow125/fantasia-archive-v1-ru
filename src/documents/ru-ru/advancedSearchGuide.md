
# Руководство по расширенному поиску

---

## Введение

В Fantasia Archive есть довольно развитый поисковый движок, встроенный в большинство полей поиска, которые просматривают либо все документы, либо документы одного типа — например, поля одиночных и множественных связей на странице документа и всплывающее окно быстрого поиска.

---

## Интеллектуальное сопоставление и сортировка

Поиск работает следующим образом: вы можете ввести любое количество слов, и программа обработает каждое из них отдельно, если они разделены пробелами.

### Поиск подчиняется следующим правилам

- **Поиск нечувствителен к регистру: можно писать всё ЗАГЛАВНЫМИ или строчными буквами — это не имеет значения**
- **Слова могут идти в любом порядке**
  - Пример: `Dark scary castle` будет найден, даже если набрать `scary castle dark`
- **Даже части слов приводят к успешному результату**
  - Пример: `Dark scary castle` будет найден, даже если набрать `sca tle ark`
- **Документы сортируются по следующим правилам:**
  - **Точное совпадение важнее всего остального**
    - Пример: `Dark scary castle` — точное совпадение для запроса `dark scary castle`
  - **Совпадение целого слова важнее фрагментов**
    - Каждое полностью совпавшее слово считается отдельно: чем больше полных совпадений у документа, тем выше он в списке
    - Пример: `Dark scary castle` имеет 2 совпадения целых слов для запроса `dark scary tle`
  - **Фрагменты находятся в конце списка**
    - Каждый совпавший фрагмент считается отдельно: чем больше фрагментов у документа, тем выше он в списке
    - Пример: `Dark scary castle` имеет 2 совпадения фрагментов для запроса `sca tle`
- **В поиск можно включить поле `Другие имена`, поставив перед строкой поиска символ `@`**
  - Пример: `@Vampire lair` (если у вашего `Dark scary castle` в «Других именах» записано `Vampire lair`, поиск найдёт его именно так)

## Фильтрация

Помимо расширенного поиска, Fantasia Archive предлагает мгновенную фильтрацию по множеству атрибутов для дальнейшего сужения результатов.

- **ВНИМАНИЕ: все приведённые ниже значения фильтров (включая полнотекстовую фильтрацию из следующего раздела) поддерживают совпадение любой части введённого текста с любой частью значения**
  - Пример: `>nada` совпадёт с `Continent > North America > Canada > Toronto`

### Фильтрация работает следующим образом и подчиняется этим правилам

- **Ни один из приведённых ниже условий фильтра не конфликтует с обычным поиском по словам**
- **Одновременно можно использовать только по одному экземпляру каждого фильтра, но разные фильтры могут действовать в одно и то же время**
- **Фильтр нечувствителен к регистру: можно писать всё ЗАГЛАВНЫМИ или строчными буквами — это не имеет значения**
- **Если в значении фильтра есть пробелы, замените их символом `-`**
  - Пример: вы хотите найти тег `Player Characters`. Чтобы точно совпасть с этим тегом, нужно набрать `#player-characters`
- **Иерархический путь автоматически заменяет все символы `>` в пути, поэтому они опускаются в строке фильтра**
  - Пример: вы хотите найти иерархический путь `USA > Virginia > Richmond`. Чтобы точно совпасть с ним, нужно набрать `>usa-virginia-richmond`
- **Можно использовать следующие условия фильтра**
  - `$` — символ поиска по типу документа
  - `#` — символ поиска по тегу
  - `>` — символ поиска по иерархическому пути
  - `^` — символ поиска по переключателям (значения перечислены ниже)
    - `^c` — показывает только документы с включённым признаком `Это категория`
    - `^d` — показывает только документы с включённым признаком `Мёртв/Пропал/Уничтожен`
    - `^f` — показывает только документы с включённым признаком `Завершён`
    - `^m` — показывает только документы с включённым признаком `Второстепенный документ`, которые обычно скрыты и отфильтрованы

## Полнотекстовая фильтрация

Эта функция предназначена в основном для тех, кому нужен полноценный поиск, способный пройти по любому полю любого документа и сопоставить любое значение практически где угодно. Полнотекстовая фильтрация позволяет немного сузить поиск, пролистав всю базу документов и точно указав нужное.

### Несколько слов предостережения

**Полнотекстовый поиск — очень мощный, но и очень требовательный инструмент: чем больше становится ваш проект, тем требовательнее он будет. Это значит, что если в проекте, например, 2000+ документов и алгоритму поиска придётся пройти по всем ним, полнотекстовый поиск может занять несколько секунд до перезагрузки результатов — учитывайте это при использовании функции: данных может оказаться ОЧЕНЬ много.**

### Фильтрация работает следующим образом и подчиняется этим правилам

- **Полнотекстовый поиск можно сочетать с любыми другими фильтрами и/или обычными поисковыми запросами**
- **Одновременно в поиске может присутствовать только один полнотекстовый фильтр**
- **Фильтр нечувствителен к регистру: можно писать всё ЗАГЛАВНЫМИ или строчными буквами — это не имеет значения**
- **В случае списков и множественных связей все введённые значения для поиска объединяются в одну большую текстовую строку**
  - Пример с полем `Local currencies`:
    - Исходные значения: `Canadian Dollar` `American Dollar` `Euro` `Klingon Darsek`
    - Преобразованные значения: `canadian-dollar-american-dollar-euro-klingon-darsek`
- **Следующие условия фильтра должны использоваться внутри поискового запроса**
  - `%` — символ начала полнотекстового поиска
  - `:` — символ разделения имени поля и значения поля
- **Можно использовать точный поиск**
  - И имя поля, и его значение можно заключить в отдельные ограничители
  - Пример точного поиска обоих: `%"local-currencies":"some-currency"
  - Пример точного имени поля: `%"local-currencies":some-currency
  - Пример точного значения поля: `%local-currencies:"some-currency"

- **Если в значении фильтра есть пробелы, замените их символом `-`**
  - Пример: вы хотите найти поле `Local Currencies` со значением `Canadian Dollars`. Чтобы точно совпасть, нужно набрать `%local-currencies:canadian-dollars`
- **Можно выполнить полнотекстовый поиск по всем полям сразу, указав `%:canadian-dollars`**
- **Список полей/типов полей, с которыми полнотекстовый поиск не работает:**
  - Тип поля `Break` (это крупные заголовки, встречающиеся по всему документу)
  - Тип поля `Tags` (для него есть более совершенный фильтр по тегам)
  - Тип поля `Switch` (в нём нет текстовых значений, да и частично он покрыт поиском по переключателям)
  - Поле `Name` (оно и так основная цель поиска, а обычный поиск по нему гораздо совершеннее)
  - Поле `Belongs under` (его покрывает гораздо более продвинутый поиск по иерархическому пути)
